# Antigravity MCP через SSH на macOS

На Mac работают Codex, исходный MCP и `agy`. SSH открывает локальный SOCKS5-порт: запросы `agy` выходят в интернет через сервер, а файлы проекта остаются доступны локально. Серверный opencodex для этого не нужен. Используйте свою учётную запись Antigravity.

## 1. Получите доступ к серверу

Попросите администратора прислать адрес SSH-сервера, имя **вашего** пользователя, порт, отпечаток ключа сервера и ожидаемый исходящий IP. Нужен доступ с разрешённой пересылкой TCP. Если это общая машина, администратор должен ограничить доступ вашей учётной записи: туннель не должен давать доступ к чужим локальным сервисам, RDP, приватной сети или метаданным облака. Не используйте учётную запись владельца. Если ограниченный доступ ещё не подготовлен, используйте свой сервер.

Создайте отдельную пару ключей, если у вас её ещё нет. Не перезаписывайте существующий файл:

```sh
ssh-keygen -t ed25519 -f ~/.ssh/agy_tunnel -C agy-tunnel
```

Администратору передайте **только** файл `~/.ssh/agy_tunnel.pub`. Добавьте в `~/.ssh/config` отдельную запись, заменив адрес, пользователя и порт на выданные вам значения:

```sshconfig
Host agy-egress
    HostName ssh.example.org
    User YOUR_SSH_USER
    Port 22
    IdentityFile ~/.ssh/agy_tunnel
    IdentitiesOnly yes
    AddKeysToAgent yes
    UseKeychain yes
    ServerAliveInterval 20
    ServerAliveCountMax 3
```

Если у ключа задан пароль, сохраните его в связке ключей macOS командой `/usr/bin/ssh-add --apple-use-keychain ~/.ssh/agy_tunnel`.

## 2. Проверьте маршрут вручную

Убедитесь, что локальный порт 1088 свободен: `lsof -nP -iTCP:1088 -sTCP:LISTEN` не должен показывать слушающий процесс. Если порт занят, выберите свободный и замените 1088 во всех примерах, включая plist.

В первом окне терминала выполните:

```sh
ssh -NT -o ExitOnForwardFailure=yes -D 127.0.0.1:1088 agy-egress
```

При первом подключении сверьте отпечаток с полученным от администратора. После успешного входа команда остаётся запущенной и обычно ничего не печатает. Во втором окне проверьте исходящий IP:

```sh
curl --fail --silent --show-error --max-time 15 --noproxy '' \
  --proxy socks5h://127.0.0.1:1088 https://checkip.amazonaws.com
```

Ответ должен совпасть с исходящим IP сервера. Если администратор ограничил список доступных адресов, для этой проверки он должен разрешить `checkip.amazonaws.com:443` или предоставить свой адрес проверки.

## 3. Включите туннель при входе в macOS

Остановите ручной туннель через Ctrl+C в первом окне. В каталоге клона этого репозитория выполните:

```sh
mkdir -p ~/Library/LaunchAgents
cp examples/local.antigravity.socks.plist ~/Library/LaunchAgents/
plutil -lint ~/Library/LaunchAgents/local.antigravity.socks.plist
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/local.antigravity.socks.plist
```

[LaunchAgent](../examples/local.antigravity.socks.plist) запускает SSH под вашим пользователем и восстанавливает соединение после обрыва. Повторите проверку IP. Если порт не появился, проверьте имя `agy-egress`, сохранённый ключ сервера и доступ к SSH-ключу без интерактивного запроса.

## 4. Подключите существующий MCP

Для первой установки выполните [инструкцию из README](../README.md#установка-вручную). Если уже используете клон публичного репозитория, проверьте `git status --short` и обновите чистый клон через `git pull --ff-only`. Проверьте команду запуска через `codex mcp get antigravity`: она должна указывать на Python и файл сервера из обновлённой установки. Не заменяйте отличающуюся локальную копию вслепую.

В `~/.codex/config.toml` найдите существующую секцию `[mcp_servers.antigravity]` и добавьте строку:

```toml
env = { AGY_PROXY_URL = "socks5://127.0.0.1:1088" }
```

Если у сервера уже задано `env`, добавьте переменную в существующую таблицу. Сохраните прежние `command` и `args`. Перезапустите Codex Desktop и попросите: «Через Antigravity MCP найди официальную инструкцию по установке Antigravity CLI и дай ссылку». Убедитесь, что ответ вернул именно `antigravity_grounded_search`, без перехода на другой инструмент. Выбор моделей и запросы используют один прокси; системный прокси macOS не меняется.

## 5. Если используете `agy` ещё и из терминала

Настройка MCP действует только на запущенный им CLI. Чтобы команда `agy` в интерактивном zsh тоже использовала туннель, добавьте в `~/.zshrc`:

```zsh
agy() {
  local p=socks5://127.0.0.1:1088
  HTTP_PROXY=$p HTTPS_PROXY=$p ALL_PROXY=$p \
  http_proxy=$p https_proxy=$p all_proxy=$p \
  NO_PROXY=localhost,127.0.0.1,::1 no_proxy=localhost,127.0.0.1,::1 command agy "$@"
}
```

Откройте новое окно терминала, войдите в собственный аккаунт через `agy`, если нужно, и проверьте: `agy --print 'Ответь только OK'`. Переменные действуют на один запуск, исходный бинарник остаётся на месте.

## Откат

Удалите только `AGY_PROXY_URL` из конфигурации MCP и функцию `agy` из `~/.zshrc`, если добавляли её. Перезапустите Codex и откройте новое окно терминала. Чтобы остановить автозапуск туннеля:

```sh
launchctl bootout "gui/$(id -u)/local.antigravity.socks"
rm ~/Library/LaunchAgents/local.antigravity.socks.plist
```

Если IP верный, но Google всё ещё отклоняет запрос по локации, проверьте доступность сервиса для своей учётной записи. Успешная проверка IP подтверждает маршрут, а не доступность подписки.
